# context

`generate_context.sh` собирает каталог проекта в один Markdown-файл: дерево
структуры плюс содержимое всех текстовых файлов. Удобно, когда нужно быстро дать
LLM или коллеге полный контекст небольшого проекта одним файлом.

## Требования

- `bash`
- `file` — для определения бинарных файлов (есть в macOS и большинстве дистрибутивов Linux)

## Использование

```bash
chmod +x generate_context.sh          # один раз

./generate_context.sh <путь_к_папке> [выходной_файл.md]
```

По умолчанию результат пишется в `project_context.md` в текущем каталоге.

```bash
./generate_context.sh .                       # → ./project_context.md
./generate_context.sh ~/dev/myapp context.md  # → ./context.md
```

## Что не попадает в вывод

- служебный мусор: `.git/`, `node_modules/`, `__pycache__/`, `.venv/`, `venv/`,
  `.idea/`, `.vscode/`, `.DS_Store`, `*.log`, `*.pyc`, lock-файлы;
- типовые секреты: `.env` и `.env.*`, `*.pem` / `*.key` / `*.pfx` / `*.p12`,
  `id_rsa` / `id_ed25519`, `.netrc`, `.pgpass`, `.npmrc`, `.pypirc`, `.aws/`,
  `.ssh/`, пути с `credentials` и `secret.` / `secrets.`;
- бинарные файлы (определяются через `file`);
- сам выходной файл.

Список задаётся переменной `IGNORE_PATTERN` (регулярное выражение) в начале
скрипта — дополняйте под свой проект.

## ⚠️ Секреты

Фильтр секретов — это эвристика по именам файлов, а не гарантия. Нестандартно
названные файлы с ключами и паролями (`config.prod.json`, `settings.py` с
секретом внутри и т.п.) скрипт не распознает. **Просматривайте получившийся файл
глазами** перед тем, как отправлять его в чат, коммитить или пересылать.

## Ограничения

- содержимое больших файлов вставляется целиком, без обрезки;
- фильтрация идёт по именам и путям, а не по содержимому файлов;
- дерево строится через `find` + `sed` — это приблизительная визуализация;
- каталоги без доступа на чтение пропускаются (`find: Permission denied` в stderr).
